# VLESS-XHTTP + 3x-ui + сайт по ключевым словам

Исправленная версия для **нового VPS**. Один самостоятельный `install.sh`; Python-код генератора встроен в него.

Версия подготовлена 24 сентября 2026 года под **3x-ui v3.8.5**. Архив панели закреплён по версии и SHA-256 для amd64/arm64. Установка не скачивает и не исполняет меняющийся `master/install.sh`. Для перехода на другой релиз нужно сверить API и обновить контрольные суммы.

## Требования

- Ubuntu 22.04/24.04 или Debian 12/13, systemd, amd64/arm64, root, интерактивный SSH-терминал. Это целевые системы, а не список уже протестированных образов.
- Чистый сервер без существующей установки x-ui. Порты TCP 80, 443, 8443, 2053, 2096 и 10000 свободны до начала установки. `ss` и `flock` обычно уже есть в базовом образе.
- A-запись домена указывает на VPS. Если есть AAAA, она также должна вести на этот сервер с доступным IPv6. Скрипт показывает разрешение DNS, но не доказывает корректность всех записей: окончательная проверка — выпуск сертификата.
- Для описанной схемы: Cloudflare DNS only. Это упрощает выпуск сертификата и IP-ограничения; утверждение, что Cloudflare Proxy всегда несовместим с Let's Encrypt, неверно.
- В сетевом экране хостинга доступны TCP 80/443, а 8443 — с административных IP. SSH-порт сохраняйте открытым.
- Сервер может скачивать пакеты и архив GitHub, обращаться к Let's Encrypt и `https://example.com/` для проверки туннеля. Для генерации нужен доступ к Pollinations.

## Установка одной командой

Сначала замените `install.sh` в своём репозитории `dexxdd/custom-AI-VPS-tuner-` на файл из этого комплекта. Пока исправление не опубликовано, команда ниже скачивает содержимое существующего репозитория, а не приложенный здесь файл.

После публикации пользователь подключается к VPS по SSH и вставляет **одну команду** (под root или пользователем с sudo):

```bash
bash -c 'set -e; S=; [ "$(id -u)" -eq 0 ] || S=sudo; if ! command -v curl >/dev/null; then $S apt-get -o DPkg::Lock::Timeout=300 update; $S apt-get -o DPkg::Lock::Timeout=300 install -y curl ca-certificates; fi; f=$(mktemp); trap '\''rm -f -- "$f"'\'' EXIT; curl -fL --proto "=https" --connect-timeout 15 --max-time 120 --retry 2 https://raw.githubusercontent.com/dexxdd/custom-AI-VPS-tuner-/main/install.sh -o "$f"; $S bash "$f" </dev/tty'
```

Команда при необходимости устанавливает curl, полностью скачивает файл, запускает его с правами root и затем удаляет временную копию. При ошибке скачивания установка не начинается. Требуются APT и, для пользователя без root, установленный sudo с разрешением на административные команды.

Мастер последовательно спрашивает:

1. Домен. Ошибочный домен или отсутствие DNS позволяют повторить ввод.
2. IP/подсети доступа к панели или явное `all`.
3. Город, бренд, нишу и стиль сайта; Enter подставляет случайный набор.
4. Способ создания сайта: нейросеть или встроенный шаблон.
5. При выборе нейросети — скрытый ввод ключа и ID модели.

Если сертификат не выпускается, можно исправить DNS/доступность порта и повторить попытку, не начиная установку заново. Все ответы читаются через `/dev/tty`; загрузка скрипта не забирает ввод пользователя. Остальные обязательные ошибки останавливают установку с указанием этапа.

## Запуск локального файла

Загрузите **этот исправленный** `install.sh` на VPS, затем выполните:

```bash
sudo bash install.sh vpn.example.com
```

Вместо `vpn.example.com` укажите свой домен или опустите аргумент, чтобы мастер запросил его. Для IPv6 разрешены обычные адреса и CIDR. `all` явно открывает панель всем IP; пустой ввод без определённого SSH-адреса не принимается.

Ссылка на исходный GitHub-репозиторий пользователя по-прежнему скачивает старый скрипт, пока вы сами не замените файл в репозитории. Эта исправленная версия туда не опубликована.

## Как устроено подключение

```text
Интернет → Nginx :443, доверенный TLS
             ├─ / → статический сайт
             └─ /случайный-путь/ → Xray 127.0.0.1:10000, VLESS-XHTTP

Администратор → Nginx :8443, HTTPS + список IP
                   └─ /случайный-путь-панели/ → 3x-ui 127.0.0.1:2053

Let's Encrypt → Nginx :80 → постоянный каталог ACME
```

Для клиента используется XHTTP `packet-up`, TLS и ALPN `http/1.1`: это соответствует HTTP/1.1-проксированию Nginx. `flow` пустой. H2/H3 и REALITY в этой версии не настраиваются. Подключение VLESS требует приложения с поддержкой XHTTP; само по себе оно не включает системный VPN/TUN на телефоне или компьютере.

Внутри панели inbound имеет адрес `127.0.0.1:10000` и `security: none`: TLS завершается на Nginx. Не меняйте эти значения на внешний порт. В `externalProxy` также переданы внешний домен, порт 443 и TLS для формирования ссылок панелью. Основная проверяемая ссылка выводится самим установщиком.

## Генератор сайта

С ключом скрипт делает один запрос к `https://gen.pollinations.ai/v1/chat/completions`, разбирает JSON-ответ, проверяет полноту HTML и отбрасывает очевидное активное содержимое. ID модели запрашивается отдельно; значение по умолчанию `openai`, доступность и стоимость зависят от сервиса. Неуспех генерации не выдаётся за успех ИИ.

Без ключа, при сетевой ошибке, неверном ответе или запрещённом содержимом используется встроенный адаптивный шаблон. Он выбирает русский при наличии кириллицы, иначе английский. Автоматический японский/немецкий/французский язык — пожелание в запросе к ИИ, не гарантия локального шаблона.

Для статического сайта JavaScript и отправка форм заблокированы политикой CSP. Обычная генерация HTML не создаёт работающий сервер обработки заявок. Результат ИИ следует просмотреть: фильтр не доказывает достоверность текста или безупречность дизайна. Ключ не записывается в сайт или файл доступа; заданные город, бренд, ниша и стиль отправляются Pollinations. Бесплатность сервиса не гарантируется.

## Доступ и обслуживание

После установки выводятся HTTPS-адрес панели, пароль, VLESS-ссылка и QR-код. Файлы на VPS доступны только root:

- `/etc/vless-installer/access.txt` — адрес панели и пароль;
- `/etc/vless-installer/connection.txt` — VLESS-ссылка;
- `/etc/vless-installer/client.json` — конфигурация клиента Xray, локальный SOCKS `127.0.0.1:10808`;
- `/etc/vless-installer/selftest.log` — журнал тестового клиента.

Веб-сайт: `/var/www/vless-site/index.html`. Конфигурация Nginx: `/etc/nginx/sites-available/vless-installer`.

Список административных IP проверяет Nginx по реальному адресу TCP-соединения. При изменении вашего IP измените `allow` в конфигурации Nginx и выполните `sudo nginx -t && sudo systemctl reload nginx`. Не включайте перед панелью CDN без отдельной настройки доверенных прокси и проверки ограничений.

Скрипт не включает выключенный UFW и не меняет политику SSH. Если UFW уже активен, добавляет разрешения для 80/443/8443; на 8443 доступ дополнительно ограничен Nginx. Произвольные существующие nftables/iptables и сетевой экран хостинга автоматически не перенастраиваются. Публичные подписки 3x-ui отключаются через API до завершения настройки клиента.

Служба управляется через `systemctl`, бинарный CLI — `/usr/local/x-ui/x-ui`. Оболочка меню `/usr/bin/x-ui` не устанавливается. Для дополнительной настройки используйте веб-панель. Автообновление панели не настраивается. В панели остаётся служебный API-токен `vless-installer`; после успешной установки его можно удалить в Settings → API Tokens, установщик повторно его не использует.

Сертификаты продлевает `certbot.timer`, после продления Nginx перечитывает их через deploy hook. Проверьте на VPS:

```bash
sudo certbot renew --dry-run
sudo systemctl status certbot.timer
```

## Проверки и границы уверенности

В среде проверки выполнены **12 автоматических тестов Python-частей**, включая ошибочные домены и CIDR, экранирование HTML, успех/сбой/тайм-аут имитированного API ИИ, согласованность UUID/путей/режима клиента и сервера, отказ при ошибке API панели и сохранение остальных настроек панели. Реальный запрос к платному ИИ не выполнялся.

Полный установщик на Linux/VPS пока не запускался. `bash -n` в этой Windows-среде также выполнить не удалось: доступный shell завершился при инициализации с `Win32 error 5`. Поэтому версия не объявляется проверенной установкой «под ключ».

На реальном VPS установщик сам проверяет конфигурацию Nginx, запуск служб, доверенный HTTPS сайта и передачу запроса через временный клиент **SOCKS → VLESS-XHTTP → Nginx → Xray → example.com**. Тест подключается к локальному адресу VPS с настоящим SNI и проверкой сертификата. Отказ любого обязательного шага завершает установку с ошибкой. Недоступность example.com тоже приведёт к отказу финальной проверки: см. журнал и доступность исходящего Интернета.

Даже успешный локальный тест не проверяет сетевой экран провайдера и сеть вашего телефона. После установки импортируйте ссылку в совместимый клиент, проверьте загрузку сайтов и внешний IP, затем доступ к панели с разрешённого и запрещённого IP. Сайт и XHTTP не гарантируют необнаружимость или работу у любого оператора.

## Повторный запуск и ошибки

Это установщик нового сервера, не обновлятор и не механизм отката. Повторный запуск при наличии каталога состояния или x-ui **останавливается**, а не удаляет клиентов, сайт или пароль.

После ошибки уже установленные пакеты и созданные настройки могут остаться. Посмотрите указанную стадию, `sudo journalctl -u x-ui -u nginx -n 100 --no-pager` и `sudo nginx -t`. Для повторной полной установки на тестовом сервере используйте исходный чистый снимок VPS; на рабочем — исправляйте конкретный этап, сохранив данные. Не удаляйте базу панели ради повторного запуска.

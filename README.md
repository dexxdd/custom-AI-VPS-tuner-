# VLESS-XHTTP + 3x-ui + сайт по ключевым словам

Интерактивная установка на **чистый VPS или сервер с существующей 3x-ui**. Один самостоятельный `install.sh`; Python-код генератора встроен в него.

Версия подготовлена 24 сентября 2026 года под **3x-ui v3.8.5**. Архив панели закреплён по версии и SHA-256 для amd64/arm64. Установка не скачивает и не исполняет меняющийся `master/install.sh`. Для перехода на другой релиз нужно сверить API и обновить контрольные суммы.

**Статус:** кандидат для испытания на тестовом VPS. Полная установка и импорт в Incy ещё не проверены. Подробности повторного аудита — в `AUDIT.md`; `REVIEW.md` описывает исходный скрипт.

## Требования

- Ubuntu 20.04/22.04/24.04/26.04 или Debian 11/12/13, systemd, amd64/arm64, root, интерактивный SSH-терминал. Это целевые системы.
- В режиме чистой установки нет существующей x-ui; порты TCP 80, 443, 8443, 2053, 2096 и 10000 свободны. Для режима дополнения требования описаны ниже. `ss` и `flock` обычно уже есть в базовом образе.
- A-запись домена указывает на VPS. Если есть AAAA, она также должна вести на этот сервер с доступным IPv6. Скрипт показывает разрешение DNS, но не доказывает корректность всех записей: окончательная проверка — выпуск сертификата.
- Для описанной схемы: Cloudflare DNS only. Это упрощает выпуск сертификата и IP-ограничения; утверждение, что Cloudflare Proxy всегда несовместим с Let's Encrypt, неверно.
- В сетевом экране хостинга доступны TCP 80 и выбранный HTTPS-порт (443 по умолчанию); при чистой установке также 8443 с административных IP. SSH-порт сохраняйте открытым.
- Сервер может скачивать пакеты и архив GitHub, обращаться к Let's Encrypt и `https://example.com/` для проверки туннеля.

## Выбор режима перед установкой

В начале мастер предлагает:

```text
1 — чистый VPS: установить 3x-ui, XHTTP и сайт
2 — 3x-ui уже установлена: сохранить всё и добавить XHTTP и сайт
```

Режим 2 объединяет варианты «панель уже есть» и «сохранить прежние подключения»: удаление прежних пользователей и подключений не предлагается. Он поддерживает **локальную systemd-установку 3x-ui v3.8.5 со стандартной SQLite `/etc/x-ui/x-ui.db`**, без переопределений БД. Другая версия, Docker, PostgreSQL и нестандартные размещения требуют отдельной адаптации; панель автоматически не обновляется.

В режиме дополнения:

- Пользователь вводит текущий URL панели с её секретным путём и API-токен из Settings → API Tokens. Соединение принудительно направляется на этот VPS через loopback с сохранением исходного SNI/проверки TLS. Панель должна быть доступна таким способом; если её прежний reverse proxy блокирует loopback по IP, сначала настройте локальный административный доступ. Самоподписанные сертификаты не обходятся. Вводите базовый URL вида `https://panel.example.com:8443/secret/`, без добавления `/panel/`, `/inbounds` и других страниц интерфейса.
- До установки системных пакетов создаются согласованная SQLite-копия БД с проверкой целостности, архив текущего Nginx и копия описания службы x-ui. После установки зависимостей, но до изменений через API сохраняется снимок списка inbound. APT вызывается с `--no-upgrade` для явно перечисленных пакетов; это не исключает изменений зависимостей и запуска служб. Каталог резервной копии выводится на экран.
- Бинарник, unit-файл, пароль, адрес и порт панели, подписки и её общие настройки не заменяются. Новый inbound, пользователь и Host добавляются через API. Имя клиента и tag содержат случайный идентификатор, чтобы не конфликтовать с прежними.
- Можно выбрать свободный внешний HTTPS-порт, например **9443**, если 443 занят. Выбранный порт попадёт в Nginx, Host, ссылку и клиентскую конфигурацию. Внутренний порт Xray выбирается автоматически. Занятые порты не освобождаются принудительно; при конфликте скрипт останавливается.
- Для сайта нужен отдельный домен/поддомен, ещё не обслуживаемый Nginx. Если порт 80 занят, допускается только Nginx. Существующий сайт и его конфигурация не переписываются. Regex `server_name` требует ручной проверки, поэтому автоматическое дополнение останавливается.
- Новый сайт и конфигурация получают отдельные каталоги с уникальным идентификатором. При повторном успешном запуске режима 2 создаётся ещё одно подключение; это не повторное применение той же конфигурации.
- После добавления проверяется, что прежние ID, клиенты, протоколы и конфигурации inbound остались прежними; счётчики трафика могут изменяться.

**Сохранение настроек не означает отсутствие перерыва связи.** Панель может применить новый inbound через перезапуск Xray; установка недостающих системных пакетов также может затронуть службы. Обновление Nginx выполняется reload. Автоматического отката нет: после сбоя новый сайт или inbound могут остаться, а скрипт сообщает этап ошибки. Резервная копия предназначена для ручного восстановления после проверки причины; не подменяйте работающую БД на лету.

## Установка одной командой

Сначала замените `install.sh` в своём репозитории `dexxdd/custom-AI-VPS-tuner-` на файл из этого комплекта. Пока исправление не опубликовано, команда ниже скачивает содержимое существующего репозитория, а не приложенный здесь файл.

После публикации пользователь подключается к VPS по SSH и вставляет **одну команду** (под root или пользователем с sudo):

```bash
bash -c 'set -e; S=; [ "$(id -u)" -eq 0 ] || S=sudo; if ! command -v curl >/dev/null; then $S apt-get -o DPkg::Lock::Timeout=300 update; $S apt-get -o DPkg::Lock::Timeout=300 install -y curl ca-certificates; fi; f=$(mktemp); trap '\''rm -f -- "$f"'\'' EXIT; curl -fL --proto "=https" --connect-timeout 15 --max-time 120 --retry 2 https://raw.githubusercontent.com/dexxdd/custom-AI-VPS-tuner-/main/install.sh -o "$f"; $S bash "$f" </dev/tty'
```

Команда при необходимости устанавливает curl, полностью скачивает файл, запускает его с правами root и затем удаляет временную копию. При ошибке скачивания установка не начинается. Требуются APT и, для пользователя без root, установленный sudo с разрешением на административные команды.

Мастер последовательно спрашивает:

1. Режим установки; в режиме дополнения — внешний порт. Затем домен: ошибочный ввод или отсутствие DNS позволяют повторить ввод.
2. В обоих режимах — IP/подсети доступа к новому VPN или явное `all`. Для новой панели применяется тот же список; доступ к ранее установленной панели не меняется.
3. Способ создания сайта: встроенный премиальный генератор (с выбором темы: IT, кофейня, архитектура, история, консалтинг или авто-подбор) или загрузка своего HTML-файла (с авто-поиском `/root/index.html` и поддержкой скачивания по ссылке с GitHub Raw).
4. Для встроенного генератора — выбор тематики (1–6), города, бренда, ниши и слогана (нажатие Enter выбирает готовые значения по умолчанию). Для своего HTML — подтверждение найденного пути или ввод ссылки.

Если сертификат не выпускается, можно исправить DNS/доступность порта и повторить попытку, не начиная установку заново. Все ответы читаются через `/dev/tty`; загрузка скрипта не забирает ввод пользователя. Остальные обязательные ошибки останавливают установку с указанием этапа.

## Запуск локального файла

Загрузите **этот исправленный** `install.sh` на VPS, затем выполните:

```bash
sudo bash install.sh vpn.example.com
```

Вместо `vpn.example.com` укажите свой домен или опустите аргумент, чтобы мастер запросил его. Для IPv6 разрешены обычные адреса и CIDR. `all` явно открывает новый VPN и, при чистой установке, новую панель всем IP; пустой ввод без определённого SSH-адреса не принимается.

Ссылка на исходный GitHub-репозиторий пользователя по-прежнему скачивает старый скрипт, пока вы сами не замените файл в репозитории. Эта исправленная версия туда не опубликована.

## Как устроено подключение

Схема чистой установки. При дополнении внешнему HTTPS можно назначить другой порт, внутренний выбирается автоматически, прежняя панель остаётся на своём адресе.

```text
Интернет → Nginx :443, доверенный TLS
             ├─ / → статический сайт
             └─ /случайный-путь/ → Xray 127.0.0.1:10000, VLESS-XHTTP

Администратор → Nginx :8443, HTTPS + список IP
                   └─ /случайный-путь-панели/ → 3x-ui 127.0.0.1:2053

Let's Encrypt → Nginx :80 → постоянный каталог ACME
```

Для клиента используется XHTTP `auto`, TLS и ALPN `http/1.1`: автоматический режим выбирает подходящий способ передачи для HTTP/1.1-проксирования Nginx. `flow` пустой. H2/H3 и REALITY в этой версии не настраиваются. Подключение VLESS требует приложения с поддержкой XHTTP; само по себе оно не включает системный VPN/TUN на телефоне или компьютере.

Внутри панели inbound имеет адрес `127.0.0.1:10000` (в режиме дополнения — другой свободный локальный порт) и `security: none`: TLS завершается на Nginx. Не меняйте эти значения на внешний порт. Скрипт создаёт через API постоянный **Host `VLESS-XHTTP-TLS`**, привязанный к ID этого inbound: внешний домен, выбранный HTTPS-порт (по умолчанию 443), `security=tls`, SNI, Host, путь, ALPN и fingerprint. Это заменяет использование устаревшего поля `externalProxy`. Ответ API проверяется: при неправильных внешних параметрах установка останавливается.

## Ссылки новых пользователей и Incy

Добавляйте пользователей в созданный inbound `VLESS-XHTTP`. В информации/QR пользователя используйте публичный Host `VLESS-XHTTP-TLS`. Host относится ко всему inbound, поэтому не требуется править домен, порт и TLS в ссылке каждого нового пользователя. UUID каждого клиента остаётся собственным. Если интерфейс дополнительно предлагает прямую ссылку backend на `127.0.0.1:10000`, её пользователям не передавайте. Для нового отдельного inbound нужна отдельная привязка Host.

Ожидаемый вид ссылки:

```text
vless://UUID@ВАШ-ДОМЕН:443?encryption=none&security=tls&sni=ВАШ-ДОМЕН&type=xhttp&host=ВАШ-ДОМЕН&path=СЛУЧАЙНЫЙ-ПУТЬ&mode=auto&alpn=http%2F1.1&fp=chrome
```

`encryption=none` означает отсутствие дополнительного VLESS Encryption, но **TLS остаётся включённым** благодаря `security=tls`. Сочетание `encryption=none&security=none` во внешней ссылке — другая ситуация: нет ни TLS, ни дополнительного шифрования. Не отключайте проверку сертификата ради импорта. Если Incy отвергает именно вариант с TLS, для диагностики нужны точный текст ошибки и версия приложения: текущая документация различает эти два параметра и указывает `none` как значение VLESS encryption по умолчанию.

Изменять только строку `encryption` на произвольное значение нельзя: дополнительное VLESS Encryption требует согласованных ключей и настроек сервера и клиента. Эта версия использует TLS, дополнительное VLESS Encryption не включает. Формат ссылки согласован с документацией Incy; реальный импорт и подключение в приложении пока не проверены.

Настройка Host готовит ссылки и QR в панели, но не рассылает их автоматически. В режиме чистой установки публичные URL подписки отключены, в режиме дополнения их прежние настройки сохраняются; речь о копировании индивидуальной VLESS-ссылки пользователя.

## Загрузка своего готового HTML

Выберите **3 — свой HTML-файл**. Установщик запущен на VPS и не может открыть `C:\Users\...` на вашем устройстве напрямую. Он будет ждать, пока вы загрузите файл.

1. Оставьте окно SSH с установщиком открытым.
2. Откройте **второе окно PowerShell на своём компьютере** и выполните, подставив свои данные:

```powershell
scp -P 22 "C:\Users\ВашеИмя\Desktop\index.html" user@IP_СЕРВЕРА:~/my-site.html
```

Для macOS/Linux:

```bash
scp -P 22 ~/Desktop/index.html user@IP_СЕРВЕРА:~/my-site.html
```

`22` — ваш SSH-порт, `user` — SSH-пользователь, `IP_СЕРВЕРА` — адрес VPS. Путь слева — файл на вашем компьютере. Справа `~/my-site.html` — файл в домашнем каталоге пользователя на сервере. При входе по ключу можно добавить `-i "путь-к-ключу"` перед путём HTML.

3. Альтернатива без команд: откройте **WinSCP или FileZilla**, подключитесь по **SFTP** с теми же адресом, портом и SSH-логином, перетащите HTML в домашний каталог пользователя. С телефона можно использовать SFTP-клиент; встроенного выбора файла с устройства внутри SSH нет.
4. Вернитесь в окно установщика. Укажите **полный путь на VPS**, например `/home/user/my-site.html` или `/root/my-site.html` для root. Не вводите туда Windows-путь.

Поддерживается один полный HTML-документ в UTF-8 размером до 20 МБ. Содержимое копируется без изменения, исходник остаётся на месте. При ошибке чтения, кодировки или размера мастер предложит исправить файл и повторить ввод пути. Для одного файла используйте встроенные CSS/JS и изображения `data:`, либо абсолютные HTTPS-адреса ресурсов. Соседние папки `images/`, отдельные `.css`/`.js` и серверный обработчик формы не загружаются автоматически. Если сайт состоит из нескольких файлов, сначала соберите автономный HTML.

Для своего HTML ограничительная CSP генератора не добавляется, поэтому авторские JS/CSS могут работать. Если сам документ содержит CSP, она сохраняется. PHP и другой серверный код не исполняются.

## Белый список VPN и firewall

Один выбранный список IP/CIDR применяется к **новому XHTTP-пути**, а при чистой установке также к новой панели. Обычный сайт открыт всем. В режиме дополнения другие inbound и прежняя панель сохраняют свою политику доступа.

Схема защиты:

- **Nginx:** `allow`/`deny` внутри XHTTP-location. Клиент вне списка получает HTTP 403 до передачи запроса Xray. Корневой сайт не ограничивается этим списком.
- **nftables:** отдельная таблица закрывает прямой доступ к внутреннему TCP-порту нового Xray со всех внешних интерфейсов, по IPv4 и IPv6. Xray слушает loopback; внешние клиенты проходят через TLS Nginx. Правила других служб не удаляются, общая политика firewall и SSH не меняются.
- **systemd:** отдельная служба применяет правила после перезагрузки. `flush ruleset` не используется. При ручном сбросе всех nftables-правил потребуется перезапустить эту службу; её имя содержит идентификатор установки.

Обычный сетевой firewall не видит URL внутри HTTPS. Закрыть общий HTTPS-порт всем, кроме списка, означало бы закрыть и сайт — поэтому список проверяется в Nginx после расшифровки TLS. Текущая схема предназначена для прямого подключения (DNS only), без CDN и внешнего reverse proxy. Заголовок `X-Forwarded-For` от внешнего клиента не считается доверенным.

В списке указывайте **публичные адреса клиентов до включения VPN**. При мобильной сети, динамическом IP или переключении Wi-Fi адрес может смениться. При CGNAT один разрешённый IP может принадлежать нескольким абонентам: UUID остаётся обязательным. `all` явно отключает IP-ограничение; прямой внутренний порт Xray всё равно закрыт. Локальные `127.0.0.1` и `::1` разрешены для проверки работоспособности; это не внешние адреса клиентов.

Список записывается в `<каталог состояния>/whitelist.txt` для справки. Рабочие правила находятся в конфигурации Nginx: для изменения отредактируйте блок `location` XHTTP и, если требуется, список панели, затем выполните `sudo nginx -t && sudo systemctl reload nginx`. Изменение одного `whitelist.txt` не применяет правила автоматически.

На VPS скрипт проверит наличие таблицы firewall и, когда тестовый `127.0.0.2` не разрешён выбранным списком, запросит с него сайт и VPN-путь: сайт должен открыться, VPN-путь — вернуть 403. После этого выполняется тест туннеля с разрешённого loopback. Эти проверки встроены в установщик; в текущей Windows-среде они не выполнялись. Внешнюю доступность нужно дополнительно проверить с реального разрешённого и запрещённого IP.

## Генератор сайта

Встроенный автономный генератор мгновенно создаёт полноценный адаптивный сайт 2026 года без внешних API-запросов и без ожидания. Доступно 5 проработанных дизайн-тем с гармоничными цветовыми палитрами, блоками статистики, карточками преимуществ с чистым SVG, секцией «О нас», интерактивным аккордеоном FAQ (на чистом HTML5 `<details>`) и футером:

1. **IT & Cloud Solutions** — облачная инфраструктура, кибербезопасность, DevOps и высокие технологии.
2. **Specialty Coffee & Bakery** — авторский кофе, свежая ремесленная выпечка и коворкинг.
3. **Архитектура и Дизайн** — архитектурное бюро, эстетика формы, проектирование интерьеров.
4. **История, Культура и Наследие** — историко-культурные исследования, экспедиции и архивы (идеально для исторических и региональных доменов).
5. **Бизнес, Право и Аудит** — корпоративный консалтинг, юридический аудит и защита активов.
6. **Случайный авто-выбор** — автоматический подбор темы и заполнение контента под указанный город.

Генератор автоматически адаптирует язык сайта: при наличии кириллицы создаётся русскоязычная версия, при вводе на латинице (например, Tokyo, Berlin, Paris) — англоязычная. Внешние зависимости от нейросетей полностью исключены, что гарантирует 100% стабильность и моментальную установку.

## Доступ и обслуживание

После чистой установки выводятся HTTPS-адрес панели, пароль, VLESS-ссылка и QR-код. При дополнении выводятся прежний адрес панели и данные нового подключения; старый пароль не читается и не меняется. Файлы на VPS доступны только root. Ниже приведены пути чистой установки; при дополнении вместо `vless-installer` используется `vless-installer-ДАТА-PID`:

- `/etc/vless-installer/access.txt` — адрес панели и пароль;
- `/etc/vless-installer/connection.txt` — VLESS-ссылка;
- `/etc/vless-installer/client.json` — конфигурация клиента Xray, локальный SOCKS `127.0.0.1:10808`;
- `/etc/vless-installer/selftest.log` — журнал тестового клиента.

Веб-сайт: `/var/www/vless-installer-site/index.html`. Конфигурация Nginx: `/etc/nginx/sites-available/vless-installer`.

Список административных IP проверяет Nginx по реальному адресу TCP-соединения. При изменении вашего IP измените `allow` в конфигурации Nginx и выполните `sudo nginx -t && sudo systemctl reload nginx`. Не включайте перед панелью CDN без отдельной настройки доверенных прокси и проверки ограничений.

Скрипт не включает выключенный UFW и не меняет политику SSH. Если UFW уже активен, добавляет разрешения для 80 и выбранного HTTPS-порта, а при чистой установке также для 8443; доступ к панели дополнительно ограничен Nginx. Произвольные существующие nftables/iptables и сетевой экран хостинга автоматически не перенастраиваются. В чистом режиме публичные подписки 3x-ui отключаются через API до завершения настройки клиента; при дополнении сохраняются.

Служба управляется через `systemctl`, бинарный CLI — `/usr/local/x-ui/x-ui`. При чистой установке оболочка меню `/usr/bin/x-ui` не устанавливается; при дополнении существующая оболочка сохраняется. Для дополнительной настройки используйте веб-панель. Автообновление панели не настраивается. После чистой установки в панели остаётся служебный API-токен `vless-installer`; после успешной установки его можно удалить в Settings → API Tokens, установщик повторно его не использует.

Сертификаты продлевает `certbot.timer`, после продления Nginx перечитывает их через deploy hook. Проверьте на VPS:

```bash
sudo certbot renew --dry-run
sudo systemctl status certbot.timer
```

## Проверки и границы уверенности

В среде проверки выполнены **21 локальный автоматический тест**, включая ошибочные домены и CIDR, экранирование HTML, успех/сбой/тайм-аут имитированного API ИИ, согласованность UUID/путей/режима клиента и сервера, отказ при ошибке API панели и сохранение остальных настроек панели. Проверяется также привязка публичного Host к inbound и отказ при неверном адресе, порте, TLS, пути или отключённой проверке сертификата. Добавлены проверки альтернативного HTTPS-порта, локального обращения к существующей панели, обнаружения изменений прежних inbound (включая включение/выключение, лимит и срок действия) и конфликтов домена Nginx. Изменения счётчиков трафика допускаются. Также проверены точное копирование своего HTML, отказ для неверного/слишком большого файла и наличие ограничений только на VPN-пути в шаблоне конфигурации. Реальный запрос к платному ИИ не выполнялся.

Полный установщик на Linux/VPS пока не запускался. `bash -n` в этой Windows-среде также выполнить не удалось: доступный shell завершился при инициализации с `Win32 error 5`. Поэтому версия не объявляется проверенной установкой «под ключ».

На реальном VPS установщик сам проверяет конфигурацию Nginx, запуск служб, доверенный HTTPS сайта и передачу запроса через временный клиент **SOCKS → VLESS-XHTTP → Nginx → Xray → example.com**. Тест подключается к локальному адресу VPS с настоящим SNI и проверкой сертификата. Отказ любого обязательного шага завершает установку с ошибкой. Недоступность example.com тоже приведёт к отказу финальной проверки: см. журнал и доступность исходящего Интернета.

Даже успешный локальный тест не проверяет сетевой экран провайдера и сеть вашего телефона. После установки импортируйте ссылку в совместимый клиент, проверьте загрузку сайтов и внешний IP, затем доступ к панели с разрешённого и запрещённого IP. Сайт и XHTTP не гарантируют необнаружимость или работу у любого оператора.

## Повторный запуск и ошибки

Это установщик и средство добавления нового подключения, не обновлятор и не механизм отката. Режим 1 останавливается при существующей x-ui. Режим 2 добавляет ещё один inbound с новым сайтом и резервной копией; повторять его для устранения частичного сбоя без проверки состояния не следует.

После ошибки уже установленные пакеты и созданные настройки могут остаться. Посмотрите указанную стадию, `sudo journalctl -u x-ui -u nginx -n 100 --no-pager` и `sudo nginx -t`. Для повторной полной установки на тестовом сервере используйте исходный чистый снимок VPS; на рабочем — исправляйте конкретный этап, сохранив данные. Не удаляйте базу панели ради повторного запуска.
